# 授受 — JUJU

ファイルを送る、受け取る。

スマホ ⇔ パソコン の**双方向ファイル転送** Webサービス。
**登録不要**ですぐ使え、ファイルは**サーバーに保存しません**(暗号化して一時中継し、受信完了または数分で自動削除)。

サービス名「授受」=「**授**ける(おくる)」と「**受**け取る(うける)」。この二字が画面の中心コンセプトです。

## 特長

- **登録・ログイン不要** — 開いてすぐ使える。
- **E2E暗号化** — ファイルは送信側ブラウザで AES-GCM 256bit 暗号化してからアップロードし、受信側ブラウザで復号。サーバーは**暗号文しか扱いません**。
- **サーバーに残さない** — 受信完了で即削除、未受信でも TTL(既定3分)で自動削除。再起動時も残骸を掃除。
- **ペアリング** — 6桁PIN + QRコードの併用。インターネット越し(スマホ4G/5G ⇔ PC)でも同一フローで動作。
- **双方向** — どちらの端末からでも「授(おくる)/受(うける)」を選べる。

## 仕組み(一時リレー方式)

```
[端末A: 授]                 [JUJU リレーサーバー]                 [端末B: 受]
  ファイル選択                 - sessionId / 6桁PIN 管理(メモリ)
  AES-GCMで暗号化  ──暗号文──▶  - 暗号文を一時保存(TTL数分)   ◀──PIN/QRで参加──
                              - 受信完了 or TTLで即削除
                ◀───────────  - 暗号文をストリーム配信  ───────▶  復号して保存
```

鍵の受け渡し:

- **QR / リンク経路(推奨・完全E2E)**: 暗号鍵は受信URLの**フラグメント (`#k=...`)** に載るため、サーバーへは送信されません。サーバーは復号不能です。
- **6桁PIN手入力経路(利便性)**: 鍵は PIN から派生(PBKDF2)。手軽な反面、原理上は低エントロピーのため、最高の秘匿性が必要な場合は QR / リンクを使ってください。短時間で自動削除・単回利用・PIN総当たりのレート制限で緩和しています。

## 使い方(ローカル)

```bash
npm install
npm start
# http://localhost:3000 を開く
```

- 片方の端末で **授(おくる)** → ファイルを選択 → 表示された **PIN / QR** を相手に渡す。
- もう片方で **受(うける)** → QRをスキャン、または6桁PINを入力 → 受信・保存。

> **HTTPS が必要**: スマホ実機でのカメラ(QRスキャン)と Web Crypto はセキュアコンテキストでのみ動作します。`localhost` は例外的に可。実機テストは Caddy / ngrok などで HTTPS 公開してください。本番は TLS 終端(Caddy / Render / Fly など)の背後に配置する前提です。

## 設定(環境変数)

| 変数 | 既定 | 説明 |
| --- | --- | --- |
| `PORT` | `3000` | 待ち受けポート |
| `JUJU_TTL_SEC` | `180` | セッション/一時ファイルの寿命(秒) |
| `JUJU_MAX_MB` | `200` | 1ファイルの最大サイズ(MB) |
| `JUJU_MAX_TOTAL_MB` | `2048` | サーバー全体の一時保持上限(MB) |
| `JUJU_RESOLVE_MAX` | `20` | PIN解決のレート制限(ウィンドウ内試行回数) |
| `JUJU_RESOLVE_WINDOW_MS` | `60000` | レート制限のウィンドウ(ms) |
| `JUJU_STORAGE_DIR` | `.tmp-storage` | 一時保存ディレクトリ |

## 構成

```
server/
  config.js     設定(環境変数)
  index.js      Express + WebSocket 起動・静的配信
  routes.js     API(セッション作成/prepare/upload/resolve/claim/download/delete)
  sessions.js   セッション管理(PIN↔id、TTL、単回ロック、WS通知)
  storage.js    暗号文の一時保存(ストリーム、DL時削除、TTLスイーパー)
public/
  index.html    授/受 UI
  style.css     和テイストのデザイン(授=朱 / 受=藍)
  app.js        画面遷移・暗号化・アップロード/ダウンロード・QR
  crypto.js     Web Crypto ヘルパ(チャンクAES-GCM、PBKDF2)
```

## セキュリティ上の注意

- ファイルは E2E 暗号化されますが、リレー方式の性質上、暗号文は短時間サーバーを通過します(数分で削除)。
- 6桁PIN経路はサーバー運用者を完全には信頼しない用途には向きません。完全E2E が必要なら QR / リンク経路を使用してください。
- 転送経路は HTTPS/WSS で保護してください(本番必須)。
